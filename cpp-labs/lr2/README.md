## 📋 Требования к программе
-	Единая программа - все задачи должны быть объединены в одном проекте
-	Интерактивное меню - при запуске отображается пронумерованный список задач с кратким описанием. Последний пункт - 0. Выход
-	Устойчивость к ошибкам - программа должна корректно обрабатывать некорректный ввод без сбоев
-	Модульность - каждая задача реализуется в отдельном классе/модуле
-	Управление потоком - после выполнения задачи пользователь выбирает: выполнить снова или вернуться в главное меню

## 📋 Требования к реализации
- Обязательное использование классов с инкапсуляцией (private/public)
- Корректная реализация конструкторов (по умолчанию, параметризованных, копирования)
- Правильное использование списков инициализации
- Реализация деструкторов для освобождения ресурсов (RAII)
- Применение наследования и полиморфизма
- Демонстрация понимания порядка вызова конструкторов/деструкторов
- Чистый и читаемый код с осмысленными именами

## 📊 Список задач для меню:

### 1. Система бронирования билетов (Кинотеатр/Авиа/ЖД)
**Тип**: наследование, полиморфизм, управление ресурсами

**Описание**: вы разрабатываете бэкенд для сервиса бронирования билетов (как Яндекс.Афиша или Tutu.ru). Разные типы билетов имеют разные правила расчета стоимости и возврата.  
**Функционал**:
-	 Базовый абстрактный класс `Ticket` с полями: номер билета, дата, цена, статус (забронирован/оплачен/возвращен)
-	 Виртуальные методы: `calculateFinalPrice()` (с учетом скидок/сборов), `canRefund()` (можно ли вернуть), `getDescription()`
-	Классы-наследники: `MovieTicket` (фильм, зал, ряд, место), `FlightTicket` (рейс, класс обслуживания, багаж), `TrainTicket` (поезд, вагон, тип места)
-	В каждом классе: конструкторы, деструктор с выводом информации об удалении билета
-	Статический счетчик проданных билетов
-	Система бронирования `BookingSystem` с возможностью:
  •	Добавить билет (полиморфный список)
  •	Отменить бронирование (с проверкой возможности возврата)
  •	Показать все билеты
  •	Посчитать общую выручку

**Демонстрация ООП**:
-	Полиморфизм: обработка разных типов билетов через базовый класс
-	RAII: автоматическое освобождение памяти при удалении билетов
-	Инкапсуляция: статус билета меняется только через методы

### 2. Система расчета зарплаты (для разных категорий сотрудников)
**Тип**: наследование, полиморфизм, фабричный метод

**Описание**: : вы пишете HR-систему для компании. У разных сотрудников разный способ расчета зарплаты: штатные (оклад), почасовики, менеджеры с процентом от продаж, фрилансеры (оплата за проект).  
**Функционал**:
- Базовый класс `Employee` с полями: имя, ID, базовая ставка
- Виртуальный метод `calculateSalary() const`
- Классы-наследники:
  •	`SalariedEmployee` (оклад + фиксированная премия)
  •	`HourlyEmployee` (ставка в час * отработанные часы)
  •	`Manager` (оклад + процент от продаж отдела)
  •	`Freelancer` (фиксированная оплата за проект)
- Класс `PayrollSystem`:
  •	Добавление сотрудников (полиморфный список)
  •	Расчет общего фонда оплаты труда
  •	Поиск сотрудника по ID
  •	Сохранение/загрузка данных в файл
  •	Генерация ведомости на выплату
-	Статический счетчик сотрудников
-	Демонстрация правильного копирования (глубокое для строк)

**Демонстрация ООП:**
-	Полиморфизм: единый интерфейс для разных типов сотрудников
-	Инкапсуляция: детали расчета скрыты внутри классов
-	Принцип открытости/закрытости: легко добавить новый тип сотрудника



### 3. Симулятор работы банкомата с разными типами карт
**Тип**: наследование, полиморфизм, обработка исключений

**Описание**: вы программируете ПО для банкомата. Разные типы карт (дебетовые, кредитные, бонусные) имеют разные правила снятия, начисления процентов и комиссий.
**Функционал**:
-	Базовый класс `BankCard` (номер карты, PIN, баланс, владелец)
-	Виртуальные методы: `withdraw(double amount)`, `deposit(double amount)`, `getBonusInfo()`
-	Классы-наследники:
  •	`DebitCard` (обычное снятие, нельзя уйти в минус)
  •	`CreditCard` (кредитный лимит, проценты при просрочке)
  •	`BonusCard` (начисление бонусов за покупки, списание бонусами)
-	Класс `ATM`:
  •	Вставка карты (проверка PIN)
  •	Меню: снять наличные, внести наличные, показать баланс, показать бонусы
  •	Выдача наличных (проверка лимитов)
  •	Печать чека
-	Пользовательские исключения: `InsufficientFundsException`, `InvalidPinException`, `CardBlockedException`
-	RAII: блокировка карты при 3 неудачных попытках PIN

**Демонстрация ООП:**
- Полиморфизм: ATM работает с любой картой через базовый класс
- Исключения: грамотная обработка ошибок
- RAII: автоматическая разблокировка при извлечении карты
